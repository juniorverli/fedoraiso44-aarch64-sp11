## EFI backend qualification

The Fedora-generated config has `CONFIG_EFI_VARS_PSTORE_DEFAULT_DISABLE=y` and `CONFIG_PSTORE_RAM=m` from the base configuration. The fragment does not add `PSTORE_RAM`. On v7.3, `drivers/firmware/efi/efi-pstore.c:22` uses the default-disable option and `:51` exposes `pstore_disable`; request `efi_pstore.pstore_disable=0` on the diagnostic command line to activate EFI pstore. The same file's `efi_pstore_info.flags` is `PSTORE_FLAGS_DMESG` only (`:250`): it does not support console or pmsg records, even when their frontends are configured. Therefore the planned pmsg sentinel cannot establish EFI backend persistence, and a hard reset without an oops or panic need not leave an EFI record. Do not infer that an absent pmsg proves EFI persistence failed. The image/GPU owners need an appropriate non-destructive validation strategy and the existing synchronized kmsg fallback; no ramoops range is authorized.


## M12 device test (private ISO `…20261030T185301Z-private`, entry `debug`, kernel 7.3.0-65.sp11.9)

Logs: `out/device-logs/m12-20261030/` (private, not in git).

- **Wi-Fi works** (operator report, 2026-10-30). The generic Fedora board file plus wifi 0002 (rfkill) and 0003 (CMA below 4 GiB) brought the interface up and it scans. The M10 crash was therefore the Windows-derived board file (firmware version mismatch, see hardware/wifi/evidence/2026-10-30-m10-board-crash.md). The derived file stays off by default.
- **Bluetooth works** (operator report). The embedded address in the private image configures the controller.
- **Keyboard:** operator reports the Type Cover froze at the start of Windows after a Linux session, not only on a Linux reboot. `sp11-ssam-shutdown` was opt-in and off in this test, so this is the no-mitigation baseline. Next test: boot with `sp11.ssam_shutdown`, shut down, enter Windows, compare.
- **CDSP (decisive):** the FIFO diagnostic (dsp patch 0002) printed `tx head=40/88 tail=8` and `rx head=tail=160` on the CDSP edge. The CDSP consumed only 8 bytes of what Linux wrote and then stopped reading, while Linux read everything the CDSP sent. This favours hypothesis C2 (the CDSP does not wake or stalls) over a GLINK protocol error on the Linux side. fastrpc still fails with -12 (`create_ept` err -110). ADSP edge completes OPEN_ACK normally.
- USB: only one USB 2 device (the boot stick) in the tree; SuperSpeed hubs stay empty. The port/orientation matrix with a USB 3 stick was not recorded in this boot.

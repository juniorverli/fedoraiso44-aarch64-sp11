## M16 closure: graphics reference, automatic brightness, boot content

- **Interrupted build recovered.** The private M16 ISO was published by re-running only steps 6b-9 of the killed build (`--post-only 20261101T164840Z`): `out/iso/sp11-fedora44-aarch64-kiwi-20261101T164840Z-private.iso`, SHA-256 `4fae6632c40073851c6164b59a12034beb306c1651077ed1b4caacafb44fc6d4`, kernel `7.3.0-65.sp11.14.fc44`, milestone M16, 12-entry flat menu.
- **Graphics, reference project (dwhinham/archiso-aarch64-sp11).** Verified from its f44 profile and archiso config: the kernel command line is `clk_ignore_unused pd_ignore_unused arm64.nopauth systemd.mask=tpm2.target`; the initramfs uses the `kms` hook and `MODULES` for the display pipeline (`msm`, `panel_edp`, `phy_qcom_edp`, `pwm_bl`, `leds_qcom_lpg`, `gpucc_*`, `dispcc_*`, `qcom_q6v5_pas`, QRTR/pmic-glink); packages include `linux-firmware-qcom` and `sp11-grab-fw`. Its **live ISO deliberately carries no GPU firmware** — the README requires running `sudo sp11-grab-fw` after installation to make the GPU work. Our M16 instead adds `gen70500_sqe.fw`, `gen70500_gmu.bin` and `qcdxkmsuc8380.mbn` to the dracut initramfs so the early in-kernel DRM open no longer fails with -ENOENT. This is a deliberate divergence: it removes the immediate error but keeps the documented reset risk of a GMU/zap power-up before userspace. A Codex Terra 6.1 (high) independent check reproduced both readings and the boot-content matrix below.
- **D27, automatic brightness removed** (`plan/decisions.md`): the operator's instruction is implemented as "no automatic brightness", not as "delete the sensor". Repository evidence contradicts the premise that the sensor was invented: `sources/windows/live-inventory/sensors/winrt-sensors.txt` reports `LightSensor: PRESENT` on `MSHW048A`, `sensorsalsdriver.inf` binds `ACPI\ACPI0008`, and the board CRD config defines a TCS3430. The image sets `ambient-enabled=false` for `org.gnome.settings-daemon.plugins.power` and locks the key; L0 now asserts both. `worker/sensors` commit `e0c499a` updated acceptance, test plan and evidence (`hardware/sensors/evidence/2026-11-01-auto-brightness-removed.md`) so ALS readings are diagnostic only and brightness must not change on cover/uncover.
- **Safe/debug boot content, verified from the published DTBs.** `m15-safe`: cameras (`isp@acb7000`, `cci@ac15000/16000`, camera LEDs) `okay`, D26 speakers `okay`, ADSP `remoteproc@6800000` and CDSP `remoteproc@32300000` `okay`, PCIe4 Wi-Fi `okay`, UART14 Bluetooth present, GPU `disabled`. `m15` (debug): the same plus GPU/GMU/zap `okay`. NPU/HTP: the CDSP and FastRPC transport are enabled, but Linux 7.3 has no accelerator driver for the HTP and QAIRT is not shipped; NPU compute remains blocked regardless of entry.

## What the M16 device incident changed

- **CCI fix (revision 15).** `cci_reset()` uses master 0's `irq_complete`, but `init_completion()` ran only for available child nodes. The `m15-safe` DTB enables CCI1 master 1 without master 0, so probe could call `reinit_completion()` on a zeroed completion and fault before any sensor probe. This is the leading hypothesis for the reported DIE and matches `i2c_qcom_cci(+)` in the warning's module list. The fix initializes every master completion after allocation, before the IRQ and reset.
- **Audio.** No audio bug found; the speaker UCM overlay is userspace. The D26 speaker path staying enabled in `m15-safe` was kept for the single-variable device test; turning it off and a camera gate remain documented fallbacks.
- **GPU/display vblank loop.** No kernel patch justified by the available fragment. The source review shows a failed firmware load does not by itself fail `msm_open()`, so removing the initramfs GPU firmware is not established to remove the loop; the recommended device diagnostic is `drm_client_lib.active=` (and separately `drm_kms_helper.fbdev_emulation=0`) on the affected entry. The firmware rollback was preserved as `image/evidence/2026-11-01-gpu-firmware-initramfs-rollback.patch`, unmerged.
- **Automatic brightness (D27).** Removed: the image ships and locks `ambient-enabled=false`; L0 checks it. The ALS remains diagnostic-only. Evidence in `hardware/sensors/evidence/2026-11-01-auto-brightness-removed.md`: the Windows WinRT inventory reports `LightSensor: PRESENT`, the board config defines a TCS3430 and Windows ships `sensorsalsdriver`; the sensor is real, the automatic response is what was removed.

## Speaker ABI resolved to EUNSUPPORTED; debug entry stabilized

- **DSP error decoded.** The status 3 returned by `APM_CMD_REGISTER_MODULE_EVENTS` is `ADSP_EUNSUPPORTED` (`sources/linux/sound/soc/qcom/qdsp6/q6dsp-errno.h:14`). A byte scan of the Surface ADSP firmware `out/firmware-root/lib/firmware/qcom/x1e80100/microsoft/Denali/qcadsp8380.mbn` finds the SP module table entries `0x070010e2` (SP), `0x070010e3` (SP VI) and `0x070010e4` (CPS router) at file offsets 0x12c6030/0x12c6020/0x12c6010, but **no occurrence of the reference diagnostics event ID `0x0800138c`**; the Windows audio miniport `qcaudminiport8380.sys` contains neither the event ID nor the module IDs. The Surface firmware supports the SP modules but not the reference SP diagnostics event, so patch 0014's fatal registration turned every WSA playback prepare into `-22`.
- **Patch 0020 (candidate).** `hardware/audio-speakers/patches/0020-ASoC-qcom-handle-unsupported-SP-diagnostics-safely.patch` maps that rejection to `-EOPNOTSUPP`, allows graph preparation to continue, and latches a guard fault so the speakers stay muted (fail-closed). Other errors stay fatal; a transport EOPNOTSUPP is kept distinct. Checkpatch `--strict` clean. Audible playback still needs device evidence that the DSP SP module and VI/CPS protection are active; the muted retest must capture the registration response and guard state.
- **Debug entry stabilization (image).** The automatic GPU two-step (`sp11.gpu_diag=1` on line 1) and the automatic CDSP restart (`sp11-cdsp-experiment.service`, `sp11.entry=debug`) were the two self-resetting diagnostic agents active only on the debug entry; the GMU/HFI start returned 0 and no oops/reset reason was logged. ## Revision 20 design review and corrections

- **Independent validation:** four Terra xhigh workers, Antigravity Sonnet 5.5 High and Gemini 3.8 Flash High, and a four-lens Sonnet workflow (camera, audio, GPU, process) plus synthesis. The synthesis is a conditional go: the hardware actions are right, but the audio fail-safe, camera docs/test order, build gates and instrumentation needed corrections. Raw reports: `out/review/antigravity-{sonnet,gemini}-rev20.md`; workflow transcript under the session subagents directory.
- **Camera:** the 0x2000 CSIPHY and 0xf000 VFE fix is confirmed and merged. The front IMX681 has a second blocker: patch 0007 converts the 1.2 GHz C-PHY link to 2.736 GHz and the clock calculation requires about 718 MHz against the 480 MHz X1E table, so the front returns `-EINVAL: Pixel clock is too high for CSIPHY` before reset, s_stream and the LED. Revision 20 validates the mapping on the rear OV13858 D-PHY path and records the front error; the front C-PHY clock/CSID fix is a rev21 worker (Terra xhigh) now running. Front-first enumeration has no deterministic libcamera mechanism; acceptance is front present, `Location::Front`, explicitly selectable, not enumeration order.
- **Audio:** `api.acp.max-volume` is not implemented in WirePlumber 0.5.19 (checked in the image's `libspa-alsa.so`), so the 0.251/1.0 values were no-ops. The real ceiling is the kernel PA 6/RX-MIX 81 and UCM digital 72. The image now sets global and per-device sink defaults to 0.0, selects the built-in sink from `pw-dump`/`wpctl inspect` (not `wpctl status -n`), verifies mute, sets 100 % on normal boots and 5 % with `sp11.audio_first_test=1`, and collects per-channel RMS/peak with `pipefail`/`PIPESTATUS` for `hw:0,1` and default. The first audible test is at minimum volume, stepwise. The round-3 audio/mic cause is still unproven; the clean audio-first boot is the discriminator, and the camera oops may have wedged PipeWire in the same boot.
- **GPU:** the second GMU start is a GPU runtime resume; the GMU is a passive supplier and is not pinned. The GPU pin is installed in the initramfs (before the ~5 s DRM open), debug-only, with readback and an `sp11.gpu_pin=0` control branch. EFI pstore is enabled only on the debug entry with `efi_pstore.pstore_disable=0 printk.always_kmsg_dump=1`; it is dmesg-only (no pmsg) and must be proven with a printk marker + warm reboot. The collector adds SBSA watchdog bootstatus, GPU/GMU runtime state, a bounded tracefs snapshot, and reset/hangcheck dmesg. No ramoops node; lazy IOMMU retained.
- **Build:** kernel `7.3.0-65.sp11.20.fc44` is building with the corrected camera patch, PSTORE/EFI pstore and lazy IOMMU; Spectra will be rebuilt for the new vermagic. The image gates accept series_rev 20, pins are updated, and L0 asserts the audio policy, GPU pin, EFI pstore args, initramfs payload, watchdog/trace collector and pstore copy. The audio dossier is being synced to the canonical UCM. Next: merge the rev20 kernel and image, build the private ISO, L0/L1, then the device matrix S0-S6/D0-D2 (LED map, clean audio first test, rear camera RGB/LED, front expected C-PHY error, GPU pin/control).

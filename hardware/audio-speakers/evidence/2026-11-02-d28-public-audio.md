## Kernel request: required semantics

Patch 0022 implements the mode contract. After successful topology parsing and before a WSA stream can prepare, the kernel reads `/chosen/sp11,speaker-policy` and scans the parsed AudioReach module table. If the property cannot be read, the guard refuses WSA playback even when SP is present; the card remains registered for microphones and DisplayPort. If the property is readable and an SP module is present, its value does not select open loop and the existing closed-loop data, diagnostics/degraded, graph, VI/CPS, calibration, fault, kill-switch and amplifier-unmute checks remain in force. If no SP module is present and the property equals `d26-open-loop-v1`, the guard selects open loop: it does not load private SP data or require SP enable, diagnostics, VI/CPS or calibration. If no SP module is present and the property is absent, unreadable or different, it refuses. The selected mode is logged once and exposed with cap readiness in guard debugfs.

The names match ordinary component kcontrols, not DAPM widget controls: `lpass-wsa-macro.c` declares `WSA_RX0/1 Digital Volume` and `WSA_RX0/1_MIX Digital Volume` in `wsa_macro_snd_controls` (`sources/linux/sound/soc/codecs/lpass-wsa-macro.c:2182-2201`); the `WSA`/`WSA2` component prefixes are the names used by the machine driver's reference calls (`sources/linux/sound/soc/qcom/x1e80100.c:42-51`). `wsa884x.c` declares `PA Volume` in its component control table (`sources/linux/sound/soc/codecs/wsa884x.c:1734-1736`), which receives the left/right `SpkrLeft`/`SpkrRight` prefix in the sound card. Component controls are added during component probe (`sources/linux/sound/soc/soc-core.c:1512-1518`); `snd_soc_card_late_probe()` runs at `:2156`, before DAPM widgets are created at `:2164`, but these caps do not target dynamic DAPM controls. The machine reference uses PA Volume controls, while the separate `EAR SPKR PA Gain` control remains constrained by patch 0005.

Every WSA path still needs successful PA (maximum 6 = 0 dB), RX digital and RX MIX (maximum 81 = -3 dB) cap installation. The required stereo WSA control names must all be found and capped; WSA2, woofer and tweeter controls are capped when present and may be absent. Any cap failure keeps the guard closed. Patch 0023 does this in `snd_soc_card::late_probe`, after card components have bound and before `snd_card_register()` exposes controls/PCM devices. A user PCM cannot race this installation; if a required control is absent or a negative return occurs, the card remains available to mic/DP users but `caps_ready` stays false and the amplifier unmute check refuses playback. `sp11.nospk` and latched amplifier faults refuse both opening and unmuting in either mode. The machine driver remains the stream gate and WSA amplifier-side guard remains the unmute gate. No public topology may load or register SP diagnostics. Closed-loop selection comes from the SP module and its model-specific private topology name; the D26 marker selects open loop only when SP is absent.

The topology callback runs after `snd_soc_tplg_component_load()` completes and selects the mode before card probe finishes; an unknown mode is the initial fail-closed state. Policy errors latch refusal but leave card registration successful so microphones and DisplayPort remain available. The guard state is singleton for the Denali machine; probe start and devm teardown clear cap readiness, and teardown mutes before card unregister. Patch 0023 installs caps in the card late-probe callback after components bind and before ALSA registers the card, preventing a PCM-open race. Any missing required control leaves cap readiness false; the card can still register for microphones and DisplayPort, while the amplifier unmute check refuses WSA playback. Re-probe and removal behavior still require muted device validation. The required patch order is the existing 0001–0018 audio series, followed by candidates 0019, 0020, 0021, patch 0022 and patch 0023. Candidates 0019–0021 are not yet in the integrated `kernel/series`. Apply/check order and static limits are recorded below. No kernel or ISO build was run.

## Muted device test and exit criteria

Operator present for any audible test. First boot speaker-off fallback; verify no WSA speaker link/bus and mic/DP where applicable. On safe and debug, before opening audio verify public model, exact `d26-open-loop-v1` marker, public topology hash, reported `open-loop` mode, `nospk` clear, no fault, initial software sink mute, enforced -12 dBFS software ceiling, PA/RX/MIX caps and actual UCM routes. Open the speaker PCM while muted, confirm successful prepare/start with no `-22`, no SP module diagnostics registration attempt (`APM_CMD_REGISTER_MODULE_EVENTS` for `0x0800138c`) and no corresponding DSP unsupported response; collect full kernel journal with timestamps and graph/module evidence. Absence of a log alone is not proof if registration lacks instrumentation: add a trace/counter or instrumented build that proves zero attempts. Record the guard mode and both open/unmute decisions. Confirm no sound while muted.

With operator present, make a single short low-level playback after deliberately unmuting: both speakers play at limited volume, no distortion or unexpected heat; stop on either. Capture a short microphone sample and verify actual signal, not merely a PCM open. Test both DP routes with a display connected before PipeWire starts. Collect mixer values, actual sink state, profile/routes, PCM and topology, and before/after journal. Separately verify `sp11.nospk`, faults, and the closed-loop experiment remain fail-closed without any audible test. A speaker playing or a clean prepare alone does not prove thermal protection.

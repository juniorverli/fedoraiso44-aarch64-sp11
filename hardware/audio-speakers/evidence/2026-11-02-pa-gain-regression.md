# Revision 18 to 19: PA gain and capture verification

Independent static and log review, 2026-11-02. **Conclusion — Inference:** the sampled PA control fell six 1.5 dB steps, a nominal 9 dB reduction, and missing PA writes on speaker enable allow that lower state to persist. The snapshots do not establish the exact event that set PA to zero, the acoustic output level, or that the late-probe cap itself reduced 6 to 0. No device changes or playback were performed.

**Verified:** both snapshots declare the PA scale minimum -9.00 dB, 1.50 dB per step and `mute=1`; the source control declares the same TLV and raw 0..31 (`sources/linux/sound/soc/codecs/wsa884x.c:1732-1737`). **Inference:** nominal scale arithmetic gives 6 = 0 dB and 0 = -9 dB, a 9 dB difference. The TLV marks its lowest step as mute; do not treat the nominal -9 dB label as proof of actual acoustic gain or of digital silence. The stereo `Speakers Volume` is the package's PA remap (`image/component-inputs/d28/audio/Surface11-WsaInit.conf:4`), consistent with the paired readings, but simultaneous alias effects need device confirmation.

**Verified:** rev19 RX0 and RX1 Digital Volume each report max 81 and value 72; RX0 MIX also reports max 81/value 72 in the same capture. Thus 81 is the cap, not the sampled operating value. The configured boot sequence writes 72 to both RX and both MIX controls (`image/component-inputs/d28/audio/Surface11-WsaInit.conf:1-10`); the WSA TLV is -84 dB plus 1 dB/step (`sources/linux/sound/soc/codecs/lpass-wsa-macro.c:447,2195-2202`), hence **Inference:** 81 = -3 dB and 72 = -12 dB. A transition from 84 to 81 at cap installation is plausible from the upstream initialization, but the log's return 1 alone does not show the exact prior raw value. Do not present it as a measured transition.

## Code path and causal limits

1. **Verified:** `snd_soc_limit_volume()` sets `platform_max` then calls the clip helper (`sources/linux/sound/soc/soc-ops.c:446-470`); the helper reads the existing value, clips only values above the max, calls the control's `put`, and returns its result (`:406-434`). Therefore a value already 0 or 6 is not lowered by a cap of 6; installing that cap alone cannot explain 6 becoming 0.
2. **Verified:** patch 0022 enumerates the required RX, MIX and left/right PA controls, selects 81 for RX/MIX and 6 for PA, and erroneously returns early on any nonzero result (`hardware/audio-speakers/patches/0022-ASoC-qcom-select-speaker-policy-from-parsed-topology.patch:254-307`). Rev18 `dmesg.txt.gz` (same boot, SHA-256 `ea37059ef4de7c1b85645fa0876661aed134dbe97a3e39408c4b2183ba38dd26`) says `speaker volume cap failed for WSA WSA_RX0 Digital Volume: 1`. **Inference:** this reports a changed control as failure, not a missing control; subsequent caps were not reached on that invocation. The rev18 PA max 31 independently confirms those PA limits were absent at snapshot time.
3. **Verified:** patch 0023 changes the error check to `ret < 0` and invokes installation at card `late_probe` (`hardware/audio-speakers/patches/0023-ASoC-qcom-install-Denali-speaker-caps-at-card-late-probe.patch:20-35,47-59,81-85`). Rev19 `dmesg.txt.gz` (SHA-256 `0cbe3e74398d34067143f91d0ce00e190e20f48106fd6170d87a0ace04729f78`) logs `selected D26 open-loop speaker mode`, four RX/MIX installed returns of 1, both PA installed returns of 0, and `speaker volume caps ready`. **Inference:** the caps were installed in this boot; PA's return 0 is consistent with no change during clipping, and does not prove a preceding 6-to-0 change.
4. **Verified:** `image/component-inputs/d28/audio/Surface11-SpeakerSeq.conf:3-16` enables DAC/BOOST and does not set PA; `:18-20` writes both PA controls to 0 on disable. Patch 0001 configures reset gain 6 (`hardware/audio-speakers/patches/0001-ASoC-codecs-wsa884x-reset-the-PA-gain-to-0-dB-instea.patch:28-47`). **Hypothesis:** a disable sequence or another state transition left PA at 0 and a subsequent enable failed to restore 6. Trace UCM writes, sequence order, and PA values before/after late probe and enable/disable to establish the actual transition; neither snapshot alone proves it. The snapshots support correlation with the revision, not exclusive causation.
5. **Verified image configuration:** `image/overlay/usr/share/wireplumber/wireplumber.conf.d/53-sp11-audio-ceiling.conf:6-13` sets route default 0.0 and `api.acp.max-volume = 1.0`; `image/overlay/usr/libexec/sp11-audio-safety:5-13` sets 5% and mutes the matching sink. The helper's order means a successful unmute without a later volume change would retain 5%; no post-unmute volume or acoustic measurement is present. Mapping a UI percentage to signal dB is implementation-dependent, so no precise attenuation is claimed here.

**Verified:** `diff -ru` of the complete `usr/share/alsa/ucm2/Qualcomm/x1e80100/` trees in `out/image-work/20261102T135440Z/description/root/` (rev18) and `out/image-work/20261102T222639Z/description/root/` (rev19 round-3 ISO; `journal/2026-11-02.md:67,98`) produced no differences. The base Mic route includes DMIC0/1 and `CaptureChannels 2` (`image/component-inputs/d28/audio/Surface11-HiFi.conf:41-53`). No capture sample demonstrates a working microphone in round 3. The safe-boot snapshot is early: a logind user existed at 33.59 s but was not yet active (`STATUS.session-user.gz`, `session-user-loginctl.txt.gz`); the same boot later records a camera `csiphy_reset` oops.

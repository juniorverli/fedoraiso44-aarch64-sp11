## Causality and microphone isolation

**Refute the asserted kernel mechanism as established:** `hardware/audio-speakers/patches/0022-ASoC-qcom-select-speaker-policy-from-parsed-topology.patch:123-132` returns success after a refused policy, explicitly leaving Mic and DP usable; `patches/0015-ASoC-qcom-x1e80100-gate-speakers-on-the-speaker-prot.patch:78-100` confines the speaker check to WSA playback. Kernel `0033` removes the D26 open-loop choice; it does not disable MultiMedia2. The card and capture PCM actually appear. A **shared UCM/ACP profile activation failure** caused by probing or enabling the refused Speaker is plausible, but no failed profile/PCM activation or session graph is captured, so this causal link is a hypothesis. An independent microphone routing, signal, session or default-selection fault is also not ruled out. No PCM capture in this boot proves the microphone works or fails electrically.

The D26 topology retains the independent Mic path: `image/component-inputs/d28/audio/Surface11-HiFi.conf:4-13,20-52` combines WSA and Mic in the HiFi verb, with Speaker `hw:${CardId},0` and Mic `hw:${CardId},1`, and DMIC0/1 enable sequences. A safe future D26 microphone-only configuration would select a UCM verb/profile that omits WSA initialization, WSA route and Speaker device while retaining the MultiMedia2 mixer, Mic DMIC sequences and capture PCM; alternatively expose only an independently verified Mic-only UCM profile via WirePlumber/ACP, avoiding Speaker probing. This is a design option, not a proven minimal fix: confirm with an isolated capture/profile trace, ensure the WSA guard remains refused, preserve DP if required, and validate default selection and stereo signal. Do not simply bypass the guard or assert that merely hiding a node avoids all WSA initialization. No D26 UCM change is justified by the current evidence.

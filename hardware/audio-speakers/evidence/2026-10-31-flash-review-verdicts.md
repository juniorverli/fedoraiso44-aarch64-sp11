F-01 and F-02 are both real. Together they meant: with the series as it was, the speakers could never start (F-01), and the day the gate was loosened to let them start, a fault mute could be undone by pause and resume (F-02). Both are fixed by moving the gate to the one place that enables the power amplifier.

## Bring-up now

1. Stage 0: the card probes, the amplifiers enumerate; PA off (register default 0 and `wsa884x_guard_hold()`).
2. Supervisor opens the V/I capture (MultiMedia5) and keeps it open: DPCM opens back end 106, `GRAPH_OPEN` carries the V/I module, the calibration is applied at prepare of that graph, graph start counts one V/I stream. Playback is still silent and refused if asked (`open_allowed`, `allowed: no`, reason "the closed-loop graph is not up").
3. `aplay` on MultiMedia1: startup and prepare pass the static check (`sp11_guard_check()`: data loaded, no fault, no `sp11.nospk`); the playback graph 105 opens with the SP module and the control link; nothing is audible because the PA is off.
4. Trigger START: the CPU DAI starts the graph (`graph_up`, `q6apm.c:817`), then, in the same loop (`soc-dai.c:801` to `:810`, CPU DAI before codec DAIs), each amplifier asks `sp11_guard_unmute_check()`: graph up, V/I running, CPS running if the topology needs it, calibration applied (measured, or nominal with `sp11.allow_nominal`), no fault. Only then the PA is enabled. Anything missing: the amplifier stays muted, `speaker stays muted: <reason>` is logged, the stream runs silently.
5. While playing: a fault (amplifier interrupt, SPv5 diagnostics event) latches and mutes; the V/I stream or the graph stopping mutes without latching; pause release, resume and a new start unmute only if all conditions hold again; after a latched fault no path unmutes before reboot.

What this does not change: the protection stays open-loop-plus-DSP (S1/D26 as written), the PA gain and volume caps of 0001, 0002, 0004, 0005 apply as before, and the userspace order (V/I capture first) is still required for sound. A late V/I start does not unmute a running stream by itself; pause and release (or a new start) does.

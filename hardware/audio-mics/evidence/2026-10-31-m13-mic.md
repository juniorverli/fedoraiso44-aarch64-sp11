# M13 device log: why no capture source reaches PipeWire

Date: 2026-10-31. Boot: M13 private ISO, kernel `7.3.0-65.sp11.10`, entry `debug` (DTB m13, microphones only). Private log set `m13-20261031/<boot id>`; the card long name contains a unit-specific board token and is not copied here. Not used: REA. Nothing built; the fix was tested with `alsaucm` from Fedora 44 `alsa-ucm-utils` 1.2.16-1 and `alsa-ucm` 1.2.16.1-1 in a container.

## Headline

The card registers and the DSP path exists, but **alsa-lib never loads any UCM file for it**. The overlay link `conf.d/x1e80100/X1E80100-Microsoft-Surface-Pro-11.conf` is named after the card *model*, and alsa-ucm's lookup never probes that name. The only fallback file, `conf.d/x1e80100/x1e80100.conf`, has no Surface Pro 11 branch. Result: `snd_use_case_mgr_open: failed to import hw:0 (empty configuration)`. Without a UCM profile PipeWire/WirePlumber (ACP) finds no usable profile and creates no node; the mixer stays untouched (`MultiMedia2 Mixer VA_CODEC_DMA_TX_0` off).

## Inference

| # | Statement | Rests on |
|:--|:--|:--|
| I1 | No node in PipeWire is the direct consequence of the empty UCM import: ACP then falls back to its legacy mixer paths (`analog-*`), which need elements this card does not have (`Master`, `Capture`, ...). The log has no `wpctl status` snapshot (no user session when the snapshot ran), so this step is not observed | V4, V6; WirePlumber 0.5.18 behaviour |
| I2 | The conf.d link was derived from upstream's `X1E80100-CRD.conf` naming, which works only when the DT `model` is at most 31 characters. `X1E80100-Microsoft-Surface-Pro-11` is 33 | V1, V8 |
| I3 | A conf.d file named with the DMI long name would also work but contains a unit-specific token that may differ between units and must not be in git; the DMI-regex branch needs no such token | V1, V9 |
| I4 | Once the profile loads, the capture path follows the verified topology (MultiMedia2 to `VA_CODEC_DMA_TX_0`, 48 kHz S16_LE, 1 to 2 channels) | `2026-10-30-mics-plan.md` |

## The fix

Files (in this worktree, under `hardware/audio-mics/userspace/`):

- `overlay-ucm-fix/usr/share/alsa/ucm2/Qualcomm/x1e80100/x1e80100.conf`: Fedora 44's file (alsa-ucm 1.2.16.1) plus one block `If.SURFACEPro11`, regex `Surface Pro, 11th Edition` on `${var:DMI_info}`, including `/Qualcomm/x1e80100/MICROSOFT-Surface-Pro-11.conf`. It replaces the file that `conf.d/x1e80100/x1e80100.conf` links to.
- `tests/ucm-syntax-test.sh`: the `alsaucm` parse test (run command in its header).
- No change to `MICROSOFT-Surface-Pro-11.conf` or `Surface11-HiFi.conf` (they are the audio-speakers owner's and are correct).

The effective UCM after the fix (verb `HiFi`, device `Mic`):

| When | Mixer controls set (exactly what `alsaucm set _verb HiFi` and enabling `Mic` run) |
|:--|:--|
| Verb enable | `MultiMedia2 Mixer VA_CODEC_DMA_TX_0` = 1 |
| Device `Mic` enable | `VA DEC0 MUX` = `VA_DMIC`; `VA DMIC MUX0` = `DMIC0`; `VA_AIF1_CAP Mixer DEC0` = 1; `VA_DEC0 Volume` = 100; `VA DEC1 MUX` = `VA_DMIC`; `VA DMIC MUX1` = `DMIC1`; `VA_AIF1_CAP Mixer DEC1` = 1; `VA_DEC1 Volume` = 100 |
| Device `Mic` disable | `VA DMIC MUX0/1` = `ZERO`; `VA_DEC0/1 Volume` = 0; `VA_AIF1_CAP Mixer DEC0/1` = 0 |
| PCM | `CapturePCM hw:${CardId},1` (card id `X1E80100Microso`), priority 100 |

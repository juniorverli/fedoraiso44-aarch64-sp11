# 1. Video Subsystem: Iris VPU and AV1 Encoder

### 1.1 Windows Driver & Firmware Architecture
Under Windows 11 on Snapdragon X Elite, video processing is divided across two distinct hardware engines:
1. **Iris VPU (Video Processing Unit):**
   - **Firmware Blob:** `qcvss8380.mbn` (short hash: `d52c2887`), accompanied by protected-path image `qcvss8380_pa.mbn` (short hash: `40f6f6d6`) in driver package `qcdx8380.inf_arm64_34a2c09c0e5b25ac`.
   - **Architecture:** Xtensa LE32 ELF image. The embedded version string confirms version `vfw-3.1:rel0092`, matching Qualcomm Iris VPU 3.1 (Gen2 architecture).
   - **Role:** Handles hardware video decoding for all major formats and hardware video encoding for H.264 and HEVC.
2. **Dedicated AV1 Encoder (VED2):**
   - **Firmware Blob:** `qcav1e8380.mbn` (short hash: `0daa48ff`) in package `qcdx8380.inf_arm64_34a2c09c0e5b25ac`.
   - **Architecture:** ELF32 machine type 106 (custom discrete controller core).
   - **Role:** Independent hardware encoder exclusively used for AV1 encoding, loaded by `qcdxkm8380.sys` via discrete initialization routines (`Ved2Av1eHwlVpuInit`, `Ved2PilLoad`).
3. **Enhanced Video Analytics (EVA):**
   - **Firmware Blob:** `evass.mbn` (short hash: `0c5e4a59`) in `qceva8380.inf_arm64_2c225ab110269463`, bound to ACPI device `QCOM0CF1` (`EVA0`) and controlled by `qceva8380.sys` (short hash: `0ad063c6`). This is computer vision / video analytics acceleration, separate from standard codec decoding/encoding.

### 1.2 Firmware Loading & Authentication Mechanism (PAS ID)
- **PAS ID:** Both Venus legacy and Iris modern video subsystems authenticate via Peripheral Authentication Service (PAS) ID **9** (`IRIS_PAS_ID` / `VENUS_PAS_ID = 9`).
- **Load Sequence:** 
  1. The OS driver reserves a contiguous physical memory buffer (`video_mem`).
  2. The firmware ELF segments are loaded using `qcom_mdt_load`.
  3. The OS issues an SCM / TrustZone call `qcom_pas_auth_and_reset(9)` to trigger QTEE signature verification and take the VPU out of reset.
  4. Memory protection is applied via `qcom_scm_mem_protect_video_var` to isolate video buffers from non-secure access.

### 1.3 Memory Regions, Clocks, and Power Domains
- **Memory Carveout:** Linux device tree `hamoa.dtsi` allocates `video_mem: video@87700000` with base physical address `0x87700000` and size `0x700000` (7 MiB), marked `no-map`.
- **Power Domains:**
  - `VIDEO_CC_MVS0C_GDSC` ("venus")
  - `VIDEO_CC_MVS0_GDSC` ("vcodec0")
  - `RPMHPD_MXC` ("mxc")
  - `RPMHPD_MMCX` ("mmcx")
- **Clocks:**
  - `GCC_VIDEO_AXI0_CLK` ("iface")
  - `VIDEO_CC_MVS0C_CLK` ("core")
  - `VIDEO_CC_MVS0_CLK` ("vcodec0_core")
- **OPP Frequencies:** Range from 192 MHz (low SVS) through 240 MHz, 338 MHz, 440 MHz up to 514 MHz (Turbo).

### 1.4 Codec Capabilities: Linux vs Windows
- **Decoding (VPU 3.1):** Both Windows and Linux Iris drivers support hardware decode for:
  - H.264 (`V4L2_PIX_FMT_H264`)
  - HEVC / H.265 (`V4L2_PIX_FMT_HEVC`)
  - VP9 (`V4L2_PIX_FMT_VP9`)
  - AV1 (`V4L2_PIX_FMT_AV1`)
- **Encoding:**
  - Iris VPU: Supports H.264 (`V4L2_PIX_FMT_H264`) and HEVC (`V4L2_PIX_FMT_HEVC`). In Windows, exposed through `qcvidencarm64xmfth2648380.DLL` (short hash: `6009b50d`) and `qcvidencarm64xmfthevc8380.DLL` (short hash: `c04ba88d`).
  - AV1 Encode: Exposed in Windows via `qcvidencarm64xmftAV18380.DLL` (short hash: `a5aebbf7`). It routes to the separate hardware engine running `qcav1e8380.mbn`. There is currently **no Linux kernel driver** for the Qualcomm discrete VED2 AV1 encoder.

### 1.5 Linux 7.3 Driver Comparison & Upstream Status
- **Driver Location:** `drivers/media/platform/qcom/iris/` in Linux 7.3.
- **Platform Data:**
  - `hamoa.dtsi` declares `iris: video-codec@aa00000` with compatible `"qcom,x1e80100-iris", "qcom,sm8550-iris"`.
  - `iris_probe.c` matches `"qcom,sm8550-iris"` to `sm8550_data` (VPU3x gen2 descriptor, 2 VPP pipes).
  - Note: Linux 7.3 also introduces `x1p42100_data` (1 VPP pipe, custom clock table `vcodec0_bse`), but `x1e80100` uses the `sm8550_data` baseline.
- **Upstream Firmware Naming:** Upstream `iris_platform_vpu3x.c` looks for `qcom/vpu/vpu30_p4.mbn` (or `vpu30_p1_s7.mbn` / `vpu30_p4_s6.mbn`). Linux-firmware distributions do not yet universally carry the OEM-signed Surface variant.
- **Why Node is Disabled in DT:** The node has `status = "disabled"` in `hamoa.dtsi` because VPU firmware is OEM-signed and system-specific; board files must opt in when appropriate firmware is provided.

### 1.6 Device Tree Enablement & Patch Plan
1. **Device Tree Enablement:**
   In `x1-microsoft-denali.dtsi` (or `x1e80100-microsoft-denali-oled.dts`), enable the node and supply the OEM firmware name override supported natively by `iris_firmware.c`:
   ```dts
   &iris {
       status = "okay";
       firmware-name = "qcom/x1e80100/microsoft/denali/qcvss8380.mbn";
   };
   ```
2. **Firmware Distribution:**
   Extract `qcvss8380.mbn` from Windows DriverStore (`qcdx8380.inf_arm64_*`) and package it into `/lib/firmware/qcom/x1e80100/microsoft/denali/qcvss8380.mbn`.
3. **Optional Driver Optimization:**
   Add explicit `"qcom,x1e80100-iris"` platform data configuring 4 VPP pipes (`num_vpp_pipe = 4`) and matching SM8750 core mbps throughput limits instead of falling back to SM8550 (2 pipes).

### 1.7 Graded Findings (Video)
- **Verified:**
  - `qcvss8380.mbn` (short hash: `d52c2887`) is the Iris VPU 3.1 firmware (`vfw-3.1:rel0092`).
  - `qcav1e8380.mbn` (short hash: `0daa48ff`) is the separate AV1 encoder firmware for the discrete VED2 block.
  - Signing and authentication uses PAS ID 9 (`IRIS_PAS_ID` / `VENUS_PAS_ID`).
  - Linux 7.3 Iris driver supports decode of H.264, HEVC, VP9, AV1, and encode of H.264 and HEVC.
  - Video carveout is 7 MiB at physical address `0x87700000` (`video_mem`).
- **Inference:**
  - Specifying `firmware-name = "..."` in the Denali DT allows the driver to boot `qcvss8380.mbn` directly without modifying C kernel code, as `iris_firmware.c:iris_detect_firmware()` checks `of_property_read_string_index(..., "firmware-name", 0, ...)` before default names.
  - AV1 hardware encoding will remain non-functional in Linux until a discrete driver for Qualcomm VED2 is developed.
- **Unknown:**
  - Whether TrustZone on Denali requires vendor-specific authentication keys for `qcvss8380.mbn` that reject generic Qualcomm reference `vpu30_p4.mbn` releases from linux-firmware.

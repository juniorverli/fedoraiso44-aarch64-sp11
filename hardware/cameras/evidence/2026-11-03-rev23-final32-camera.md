## Darkness, timing, selection and HDR

**Verified:** base OV13858 (`sources/linux/drivers/media/i2c/ov13858.c:58-76,1211-1255,1589-1619`) offers exposure minimum 4 lines, nominal initial 1600, max VTS minus 8, adjusted with VBLANK; analogue code 0–8191, default 128, step 1, and digital gain default 1024, with register writes only while powered. Stock helper models analogue gain code/128; the driver range is an advertised code range, not proven usable optical gain range. Patch 0013 changes per-mode line timing; Windows-derived mode timing has a ~9.6% arithmetic discrepancy (cross-check §2), not a measured error. Safe front IPA reports gain 1–15.5152, not actual applied values. The prior line-length cross-check flags IMX681 timing mismatch; its gain law and code limits remain physically unverified despite successful enumeration.

**Inference:** libcamera SoftISP AGC adjusts over frames, so slow convergence, an incorrect gain conversion/delay or exposure timing, signal clipping and wrong black subtraction/AWB can all contribute. There is no per-frame value or dark reference to establish which. `out/ref/libcamera/src/ipa/simple/algorithms/agc.cpp:68-192` is a local reference, not proof of exact installed behavior. Tuning file selection was logged for both cameras; content actually installed, gamma patch and runtime values require hashes and build provenance. Generator's black-level scaling and fitted gamma are approximations; no calibrated physical black frame, HDR comparison or chart exists. The SoftISP path does not establish Windows multi-exposure HDR or Windows tone mapping. Do not assume HDR is active or change sensor registers/gain/black/gamma on this evidence. Under stable light collect first-to-converged request metadata, measured cadence, exposure/gain limits and colour target plus raw dark/flat frames; compare a fixed manual exposure/gain supported by libcamera and matched Windows conditions. Verify histogram/black scaling and calibrated gamma against those frames.

**Verified:** safe collector logs no OV13858 NATIVE_SIZE, CROP_BOUNDS or CROP; libcamera defaults array/active to 4224x3136 and crop to active (`extra-cameras:1828-1835,1857-1858`; base pad ops `sources/linux/drivers/media/i2c/ov13858.c:1525-1530`, no selection addition in 0013). Effect on metering and FOV is unquantified; it does not establish an underexposure cause. Derive physical and per-mode rectangles with orientation/binning before implementing them, then cross-check. Do not invent dimensions.

Rootfs existence alone is insufficient.

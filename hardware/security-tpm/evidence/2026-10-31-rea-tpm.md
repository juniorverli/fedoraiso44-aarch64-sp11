# 3. TPM 2.0: Microsoft Pluton and TrEE over QSEECOM

### 3.1 Windows Architecture and Driver Hierarchy
The TPM implementation on the Surface Pro 11 is firmware-based (fTPM) integrated into Microsoft Pluton:
1. **Underlying Hardware / TrustZone Service:** There is no discrete TPM (dTPM) chip on the SPI/I2C bus. The TPM functionality is executed as a secure application named `qcom.tz.mssecapp` inside Qualcomm Secure Execution Environment (QSEE / TrustZone).
2. **Windows Driver Stack:**
   - `PlutonQc.sys` (short hash: `c47dd6f5`) binds to `Root\PlutonQc`.
   - `QcTrEE.sys` (short hash: `9cd8252c`) binds to `ACPI\QCOM04DE` (Qualcomm Trusted Execution Environment driver).
   - `WindowsTrustedRTProxy.sys` binds to `{4E815EE1-...}\{1F75CF6D-...}` (Microsoft Windows Trusted Runtime Secure Service).
   - `tpm.sys` (short hash: `90788a61`) attaches to child device `{1F75CF6D-F709-4C0C-8BCB-0CDCA1289DDD}\TrEETPM`.
3. **Communication Channel:**
   Windows `tpm.sys` communicates through the TrEE service interface (`TrEEServiceInvoke`), which `QcTrEE.sys` marshals via SCM shared memory (`SendShmBridgeCreateReqToTZ`) and dispatches to `qcom.tz.mssecapp` (`MssecServiceInvoke`, `MssecServicePpi`).

### 3.2 ACPI TPM2 Table Analysis & Start Method 14
- **ACPI Table Signature:** `TPM2`, OEM ID: `QCOM  `, OEM Table ID: `QCOMEDK2`.
- **Control Address:** `0x0000000081F10000`.
- **Start Method:** `0x0000000E` (**14** in decimal).
- **Parameters:** 12 bytes, all zeros.
- **Linux Compatibility:**
  - In Linux 7.3 `include/acpi/actbl3.h`, Start Method 13 is `ACPI_TPM2_COMMAND_BUFFER_WITH_PLUTON` and 15 is `ACPI_TPM2_CRB_WITH_ARM_FFA`. Start Method 14 is **undefined**.
  - In `drivers/char/tpm/tpm_crb.c`, start methods 2, 7, 8, 11, 13, and 15 are handled. Start Method 14 is unsupported.
  - Furthermore, Method 13 in `tpm_crb.c` assumes AMD/Intel Pluton doorbell registers, which do not exist on Qualcomm platforms where TrustZone SMC calls are required.

### 3.3 QSEECOM and UEFI Variables in Linux 7.3
- **QSEECOM Subsystem:** Linux 7.3 includes `drivers/firmware/qcom/qcom_scm.c` and `qcom_qseecom.c`.
- **Allowlist Status:** `microsoft,denali` is **explicitly allowlisted** in `qcom_scm_qseecom_allowlist[]` (`qcom_scm.c:2326`).
- **UEFI Secure App:**
  - `qcom_qseecom.c` probes and attaches to the TrustZone app `qcom.tz.uefisecapp`.
  - The client driver `qcom_qseecom_uefisecapp.c` registers with `efivars`, providing Linux full read/write access to UEFI variables.
- **Missing TPM Secure App:**
  - `qcom_qseecom.c` only lists `qcom.tz.uefisecapp`. It has no knowledge of `qcom.tz.mssecapp`.
  - There is no Linux client driver implementing the `mssecapp` TPM transport protocol.

### 3.4 Secure Boot and Firmware State
- **Secure Boot Status:** Must remain disabled on the Surface Pro 11:
  - Surface UEFI firmware rejects or crashes with Fedora shim 16.1 (Decision D18: ISO boots GRUB directly via `grubaa64.efi`).
  - GRUB lockdown under Secure Boot refuses the `devicetree` command, which is strictly needed to supply patched device trees on ARM64 Snapdragon platforms (Decision D9).
- **Impact on TPM:** Because Secure Boot is disabled and the system boots via unshimmed GRUB, measured boot (PCR 7) and BitLocker-style sealed secrets cannot be validated or utilized.

### 3.5 Plan: Document Unavailability vs Bring-up
- **Current Recommendation:** Formally document in `hardware/security-tpm/` that TPM 2.0 is **unavailable** in Linux 7.3 on Surface Pro 11.
- **Future Enablement Roadmap:**
  If TPM 2.0 support is mandated in future kernels:
  1. Add `{ "qcom.tz.mssecapp", "mssecapp" }` to `qcom_qseecom_apps[]` in `drivers/firmware/qcom/qcom_qseecom.c`.
  2. Implement an auxiliary client driver `drivers/char/tpm/tpm_qseecom.c` that communicates with `mssecapp` using `qcom_tzmem` buffers, implementing `tpm_class_ops` (`send`, `recv`, `cancel`, `status`).

### 3.6 Graded Findings (TPM)
- **Verified:**
  - ACPI TPM2 table specifies Start Method 14 (`0x0E`), control address `0x81F10000`.
  - Linux `tpm_crb.c` and `actbl3.h` do not define or support Start Method 14.
  - Windows operates the TPM via `tpm.sys` on top of `WindowsTrustedRTProxy` and `QcTrEE.sys` routing to `qcom.tz.mssecapp`.
  - `microsoft,denali` is allowlisted in `qcom_scm.c`, and `qcom_qseecom_uefisecapp.c` provides working UEFI variable access.
- **Inference:**
  - The CRB control address `0x81F10000` cannot be operated without Qualcomm SMC / QSEECOM transport mediation; standard MMIO polling is insufficient.
  - Because Secure Boot must remain off (D9, D18), the lack of a TPM does not impair system boot or basic Linux operations.
- **Unknown:**
  - The binary protocol format and command packet encapsulation expected by `qcom.tz.mssecapp` for TPM command/response buffers.

## Final Synthesis & Summary

The investigation into the Video, USB4, and TPM subsystems of the Surface Pro 11 (X1E80100 / Denali) under Linux 7.3 establishes:

1. **Video Subsystem (Iris VPU 3.1 & AV1):** The hardware video core consists of Iris VPU 3.1 (`qcvss8380.mbn`, short hash: `d52c2887`, Xtensa core) authenticated via PAS ID 9, and a separate VED2 AV1 encoder (`qcav1e8380.mbn`, short hash: `0daa48ff`). Linux 7.3 contains the `iris` driver matching `sm8550_data`, supporting H.264, HEVC, VP9, and AV1 decoding, plus H.264 and HEVC encoding. The node is disabled in `hamoa.dtsi` due to vendor signing. Enablement requires adding `status = "okay"` and `firmware-name = "qcom/x1e80100/microsoft/denali/qcvss8380.mbn"` to the Denali device tree and shipping the extracted Windows MBN. AV1 encoding has no Linux driver.
2. **USB4 / Thunderbolt:** The USB4 host router is an MMIO platform device (`QCOM0C6D` / `ACPI0015`), not a PCI device. Windows binds `QcUsb4Bus8380.sys` (short hash: `1cdf0d84`) and `QcUsb4Filter8380.sys` (short hash: `5f4aabee`) to tune the QMP USB4 combo PHY and load MCU microcode (`qcusb4-router-mcu.records.bin`, short hash: `cd4f5929`). Linux 7.3 lacks both a platform driver in `drivers/thunderbolt` and USB4 mode in `phy-qcom-qmp-combo.c`. Tunneling is unsupported, but USB-C DisplayPort Alt Mode works natively.
3. **TPM 2.0 (Pluton / TrEE):** The TPM is a TrustZone application (`qcom.tz.mssecapp`) exposed through ACPI TPM2 Start Method 14 (`0x0E`), which is unsupported by Linux `tpm_crb.c`. Linux 7.3 allowlists `microsoft,denali` for `qcom_qseecom`, enabling UEFI variables via `qcom.tz.uefisecapp`, but lacks an `mssecapp` TPM client driver. With Secure Boot disabled (D9, D18), TPM 2.0 is documented as unavailable.

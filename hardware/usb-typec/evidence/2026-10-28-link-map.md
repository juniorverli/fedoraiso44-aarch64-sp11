# USB-C end-to-end link map on Linux 7.3 (both ports)

Tree: `sources/linux` (tag `v7.3`, `c03c1a14507d`). Board file: `arch/arm64/boot/dts/qcom/x1-microsoft-denali.dtsi` (D), SoC file `hamoa.dtsi` (H). All paths below are relative to `sources/linux/`. Lines are for the unmodified v7.3 files. Grades follow `agents/protocol.md` §5.

Port naming used here: **port 0** = `pmic-glink` `connector@0` (comment "Left-side bottom port"), DWC3 `usb_1_ss0` (`a600000`), retimer on `i2c3` (`b8c000`); **port 1** = `connector@1` ("Left-side top port"), `usb_1_ss1` (`a800000`), retimer on `i2c7` (`b9c000`). The Windows ACPI numbering is URS0 = port 0, URS1 = port 1 (same MMIO bases; see `2026-10-28-windows-and-charging.md`).

## 2. Probe-time dependency that gates the internal LCD (Verified in code, confirmed on the device)

1. `drm_aux_bridge_probe` defers until its next bridge exists (`drivers/gpu/drm/bridge/aux-bridge.c:125-128`).
2. The QMP combo PHY registers an aux bridge (`phy-qcom-qmp-combo.c:5286`). The PS8830 registers one too (`ps883x.c:414`). `pmic_glink_altmode` registers an HPD bridge per connector (`pmic_glink_altmode.c:620`, added at `:685`).
3. Bridge order from the DP controller: DP controller (port 1) to QMP aux bridge (port 0) to PS8830 aux bridge (port 0) to the connector HPD bridge.
4. The DP controller probe returns `-EPROBE_DEFER` while that chain is incomplete, because for a non-eDP controller any error other than `-ENODEV` is returned (`drivers/gpu/drm/msm/dp/dp_display.c:1081-1087`).
5. The DPU master adds every available DP interface as a component (`drivers/gpu/drm/msm/msm_drv.c:949-955`) and binds only when all are present.
6. The PS8830 probe registers its switch and retimer only after a successful I2C read (`ps883x.c:444-451`), and `pmic_glink_altmode` defers on a missing retimer, mux or switch (`pmic_glink_altmode.c:634-670`).

Consequence (Verified from code): with `mdss_dp0` and `mdss_dp1` enabled, the internal eDP panel (`mdss_dp3`) appears only after both PS8830 retimers, both QMP PHYs, `pmic_glink` and `pmic_glink_altmode` have probed. No ADSP is needed for this part. The `edponly` DTB variant removes the dependency.

Device confirmation (M5, GPU-off boot `3f0e2cc1`): `devices_deferred.txt` is empty; the three DP controllers bind to `msm_dpu` within 0.7 ms of each other (`dmesg` 18:16:00.295-.299) and `ps883x` clients `1-0008` and `3-0008` hold regulators (`regulator_summary.txt`). Both retimers therefore probed (Verified, device).

## 3. What the ADSP gates (Verified in code, then device)

| Function | ADSP needed | Why |
|:--|:--|:--|
| DWC3, xHCI, eUSB2 HS PHY and repeater, QMP PHY probe, USB 2.0 devices | No | SPMI, RPMh, GCC, TCSR only |
| PS8830 probe and I2C access | No | RPMh clock, fixed GPIO regulators, I2C (`ps883x.c:388-452`) |
| PS8830 powered and routing SuperSpeed lanes | **Yes** | The driver puts the retimer into reset and cuts its supplies at the end of probe (`ps883x.c:454-455`). It is released only by `typec_retimer_set()` with a non-reset state (`ps883x.c:152-167`). The only caller is `pmic_glink_altmode`, on an ADSP `USBC_NOTIFY_IND` (`pmic_glink_altmode.c:349-394`, callback `:508-529`) |
| SS orientation (QMP lane swap, retimer reversed bit) | **Yes** | `typec_switch_set()` is called from the altmode worker (`:355`) and from `ucsi_glink` via the orientation GPIO (`ucsi_glink.c:221-226`, which runs only after UCSI registered) |
| UCSI (typec ports, partner, roles, `ucsi-source-psy-*`) | **Yes** | `pmic_glink_ucsi_register` runs only when the PDR service is UP (`ucsi_glink.c:313-330, 350-359`); that needs the `PMIC_RTR_ADSP_APPS` glink channel and the PDR service `msm/adsp/charger_pd` (`pmic_glink.c:213-264`) |
| PDR lookup `msm/adsp/charger_pd` | **Yes** (and `qcom_pd_mapper`) | Linux in-kernel mapper has the domain for `qcom,x1e80100` (`qcom_pd_mapper.c:262-266, 609-615`); Windows ships the same domain in `battmgr.jsn` (instance 74, `tms/servreg`) |
| DP Alt Mode HPD and DP lane mode | **Yes** | HPD comes from `pmic_glink_altmode_worker` (`:362-377`) |
| Battery and charger power supplies from the ADSP (`qcom_battmgr`) | **Yes** | `qcom_battmgr_pdr_notify` (`qcom_battmgr.c:1602-1612`) |
| Late-ADSP timeouts | glink send waits 5 s, UCSI read and write wait 5 s, altmode ack waits 5 s (`pmic_glink.c:18`, `ucsi_glink.c:106,175`, `pmic_glink_altmode.c:168`) | Nothing sends before PDR is UP, so a late ADSP delays features but does not time out |

Device timeline (M5, Verified): kernel start 18:15:56.62; `adsp is now up` 18:15:59.92 (3.3 s); both xHCI buses registered 18:15:59.62-.70; DP controllers bound 18:16:00.30. `ucsi-source-psy-pmic_glink.ucsi.01` and `.02` exist, so UCSI registered both connectors. No `ucsi`, `altmode` or `ps883x` error line is in `dmesg`.

## 4. Things that are not wired (Verified in the DT)

- `usb_mp` (multiport, Windows `QCOM0D08`), `usb_2` (`QCOM0D09`), `usb_1_ss2` (`QCOM0D07`) are not enabled. Windows marks `URS2` and `USB4` (`QCOM0D09`) `_STA = 0`; the multiport controller is `_STA = 0x0F` (see the Windows note).
- `smb2360_2` (`pmic@b`) is enabled (D:1074-1078) although its only consumer `usb_1_ss2_hsphy` is disabled. Harmless; whether the PMIC exists is TBD (`dmesg` shows no SPMI error).
- No `usb-role-switch` property on the DWC3 nodes, so `fwnode_usb_role_switch_get()` returns NULL and UCSI registers anyway (`drivers/usb/roles/class.c:126-137`, `ucsi.c:1848-1851`). `/sys/class/usb_role` is expected to be empty. DWC3 stays host for good (`dwc3_get_dr_mode`, `drivers/usb/dwc3/core.c:53-105`): a cable that makes the unit a device gives no gadget.
- USB4 and Thunderbolt: `CONFIG_USB4=y`, but no Qualcomm router glue (component `usb4`). `pmic_glink_altmode_enable_usb4` forwards `TYPEC_MODE_USB4` to the retimer (`pmic_glink_altmode.c:267-303`); the QMP mux treats it as USB3 only (`phy-qcom-qmp-combo.c:4835-4838`). A USB4 or Thunderbolt dock gives no tunnel.

## 4. REA limitation and release decision

The first REA MCP call (`binary_session`, before opening any target) returned:
`MCP tool call requires approval, but approval policy is never`.
No binary was opened or decompiled, no Ghidra process was started, and no REA
`evidence_id` or function address exists for this session. No Ghidra lock was
needed for that non-analysis status query. The configured server environment
also lacks `REA_GHIDRA_LANGUAGE_ID`; it must be fixed by the sources owner before
analysis, even after the permission problem is resolved (R-S1).

The required Windows boot-order investigation therefore remains blocked. See
`2026-10-29-windows-loader-inputs.md` for catalog-checked targets and the static
facts that can be established without REA. Do not present those as decompiled
behavior or port speculative constants. No kernel patch is released, no BTF
configuration changes, and no kernel build was run. The M9 deliverable is an
improved read-only collector and concrete image/tool requests; it does **not**
claim to fix CDSP.

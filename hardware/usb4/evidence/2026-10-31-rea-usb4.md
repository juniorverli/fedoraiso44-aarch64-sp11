# 2. USB4 and Thunderbolt Architecture

### 2.1 Hardware Implementation
On Snapdragon X Elite (X1E80100), the USB4 / Thunderbolt 4 architecture diverges sharply from x86 designs:
- **No PCIe NHI Endpoint:** Unlike Intel/AMD systems where the Native Host Interface (NHI) is an endpoint on the PCI bus (class 0x0C0340), Qualcomm implements the USB4 Host Router as an **on-chip memory-mapped (MMIO) platform device**.
- **ACPI Representation:** In the DSDT, `Device (UBF0)` (`_HID = "QCOM0C6D"`) represents the Host Router bus and contains child port devices:
  - `PRT0` (`_ADR = 0`, `_CID = "ACPI0015"`): Port 0 host interface.
  - `PRT1` (`_ADR = 1`, `_CID = "ACPI0015"`): Port 1 host interface.
  - `PRT2` (`_ADR = 2`, `_CID = "ACPI0015"`): Port 2 host interface.
- **PHY Hardware:** Physical transport relies on the Qualcomm QMP USB4/DP combo PHY (`qcom,x1e80100-qmp-usb3-dp-phy`).
- **Retimers:** Surface Pro 11 incorporates two external retimers:
  - Port 0: `Surface USB4 Retimer (Port 0)` (`UEFI\RES_{05575D61-005D-4BC9-8E90-13EF293AA632}`)
  - Port 1: `Surface USB4 Retimer (Port 1)` (`UEFI\RES_{59B50971-4C23-41E5-B168-0F1C0896C6EE}`)
  Both are updated via UEFI capsules and managed at runtime via UCSI / Type-C firmware interaction.

### 2.2 Windows Driver Stack
The Windows USB4 hierarchy demonstrates the driver layered separation:
1. `QcUsb4Bus8380.sys` (short hash: `1cdf0d84` / `5a282924`): Binds to `ACPI\QCOM0C6D` (`UBF0`). Manages power, clocks, resets, and enumerates the child host router device with hardware ID `USB4\QCOM0CD10001`.
2. `Usb4HostRouter.sys` (short hash: `979afa04`): Microsoft inbox Windows USB4 Host Router class driver. Manages standard connection manager operations, PCIe/DP tunneling, and time synchronization.
3. `QcUsb4Filter8380.sys` (short hash: `5f4aabee`): Installed as a mandatory `LowerFilter` on `USB4\QCOM0CD10001`. Intercepts router requests to apply proprietary hardware register initialization, configure QMP USB4 PCS/SerDes registers, execute calibration tables, and load router microcode (`qcusb4-router-mcu.records.bin`, short hash: `cd4f5929`).

### 2.3 Upstream Linux 7.3 Deficiencies
Linux 7.3 cannot drive the USB4 Host Router due to three architectural gaps:
1. **Thunderbolt Core is PCI-Only:** `drivers/thunderbolt/pci.c` registers only a `pci_driver` (`nhi_driver`). There is no `platform_driver` to bind to MMIO ACPI/DT nodes (`ACPI0015` or `qcom,x1e80100-usb4`).
2. **Missing Host Router Glue Driver:** There is no equivalent to `QcUsb4Bus` / `QcUsb4Filter` in Linux to initialize the Qualcomm-specific host router hardware and bridge it to `tb_nhi`.
3. **QMP PHY USB4 Mode Incomplete:** In `drivers/phy/qualcomm/phy-qcom-qmp-combo.c`, the driver only configures the PHY for USB 3.2 Gen2x1/Gen2x2 and DisplayPort Alt Mode (`x1e80100_usb3dpphy_cfg`). The high-speed 20G/40G USB4 SerDes/PCS register sequencing (tracked on the Linux kernel mailing list under the development series 'topic-usb4phy') is not merged into Linux 7.3.

### 2.4 Functional Alternative: USB-C DP Alt Mode
- While USB4/Thunderbolt tunneling (PCIe expansion chassis, Thunderbolt docks, eGPUs) does not work, **plain USB-C DisplayPort Alt Mode is fully operational**.
- In Linux 7.3 (as noted in `out/ref/ubuntu-surface-pro-11`), the Type-C UCSI stack (`drivers/usb/typec/ucsi/`) paired with the MSM DRM DisplayPort controller (`drivers/gpu/drm/msm/dp/`) handles HPD and multiplexes DP lanes through `phy-qcom-qmp-combo.c`. External monitors over USB-C dongles and non-Thunderbolt hubs function properly.

### 2.5 Realistic Plan
1. **Short Term (Current ISO / Fedora 44):** Document USB4 / Thunderbolt as non-functional; rely exclusively on native Type-C DP Alt Mode for external video output and USB 3.x for data.
2. **Medium Term (Upstream Backport):** Monitor upstream Linaro / Qualcomm submissions for:
   - Platform driver refactoring of `drivers/thunderbolt`.
   - Qualcomm USB4 Host Router platform wrapper.
   - QMP USB4 mode PHY driver expansion.

### 2.6 Graded Findings (USB4)
- **Verified:**
  - Host router is an MMIO device under `Device (UBF0)` (`QCOM0C6D`), with ports `PRT0`, `PRT1`, `PRT2` designated as `ACPI0015`.
  - Windows pairs Microsoft's inbox `Usb4HostRouter.sys` with Qualcomm's `QcUsb4Bus8380.sys` (bus driver) and `QcUsb4Filter8380.sys` (lower filter).
  - Linux 7.3 `drivers/thunderbolt` has no platform driver binding.
  - Surface Pro 11 uses two discrete retimers updated via UEFI GUIDs.
- **Inference:**
  - Enabling USB4 requires reverse engineering or backporting Qualcomm's entire host router register sequence and QMP USB4 mode programming; patching device tree alone is insufficient.
- **Unknown:**
  - The exact release timeline for upstream Qualcomm USB4 host router support to land in mainline Linux.

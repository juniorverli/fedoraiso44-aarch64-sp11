## Checks actually run

using GCC 16.2.1-2.fc44 and dwarves/pahole 1.32-1.fc44. Base container image
`sp11-kernel-fc44:latest` resolved to image ID

The first config enabled BTF, DWARF5, modules, ARM64/Qualcomm, OF, ACPI, SPI,
SPI-HID core/OF/ACPI, HID/multitouch, GENI SPI, regulator and DRM panel code.
`readelf -SW` verified `.BTF` in vmlinux and spi-hid.ko, spi-hid-of.ko and
spi-hid-acpi.ko. No compiler warning/error occurred. It did not enable ftrace;
a second build enabled FTRACE_SYSCALLS/TRACING/TRACEPOINTS and also exited
zero, testing actual event definitions rather than only their stubs. Both
builds enabled DRM=m and DRM_PANEL=y, so panel-follower calls were compiled
and linked against DRM, as well as both OF and ACPI frontends.

## Assessment

**Inference:** unchanged v6 is source/build compatible with the pinned v7.3
base, useful as a reproducible transport baseline. It is not sufficient to
operate this board: captured flags require quad reads and writes, v6 omits
multi-SPI and v7.3 GENI advertises no quad modes. Its generic OF reset timing
also differs from this SSDT. See the ACPI and GENI evidence files.

No full Fedora config/RPM build, QEMU boot, module loading, hardware test,
firmware upload, or independent other-runtime cross-check was performed.
Status stays **designed**, not sw-ready.
